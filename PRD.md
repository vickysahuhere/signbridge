# PRD: True Video Call Layout & Dedicated Local-Only Skeleton Overlay

## Overview & Goal
In a real-world video call between two parties (e.g., Deaf ISL signer and hearing text partner), each user needs to see the other person's face/body prominently in the large viewport, while monitoring their own camera in a compact Picture-in-Picture (PiP) window. Furthermore, on-device gesture skeleton overlays generated by MediaPipe must ONLY appear on the user's local video feed—never superimposed over the remote person's video.

## Requirements & Specifications

### 1. Two-Way Video Call Layout
- When `remoteStream` is active:
  - **Big View**: Remote partner's video stream fills the main viewport.
  - **Small View (PiP)**: Local user's camera feed appears in a Picture-in-Picture window.
- When `remoteStream` is NOT active (alone / waiting for peer):
  - Local user's camera feed fills the main viewport so they can frame themselves and test gestures.
- **View Swap Capability**:
  - The user can click a "Swap" button (or click the PiP window) to switch between Remote-Big / Local-Small and Local-Big / Remote-Small.

### 2. Isolated Skeleton Rendering (Never on Remote Person)
- The skeleton canvas (`canvasRef`) must strictly attach to and align with the **local camera video** (`videoRef`).
- When remote person is in the big view, the big view has **zero skeleton overlays**—it is a clean, crisp video of the remote partner.
- The skeleton overlay renders over the local camera feed (whether local is in the small PiP or when swapped to big).
- Skeleton toggle (`Skeleton ON/OFF`) continues to control visibility of the local skeleton overlay.

### 3. Retro '95 UI & HUD Ergonomics
- The PiP window must adhere to the Windows 95 GeoCities design system:
  - `retro-window` container, `retro-window-titlebar` with title (`Self View [You]` or `[Partner]`), `retro-btn` controls.
  - Strict 0px border-radius.
  - Quick swap button `[ ⇄ Swap ]` and PiP position options.
- The boundary alert, candidate suggestions, and subtitle overlays must remain fully functional and unclipped.

### 4. Zero Backend / Golden Invariants Compliance
- 100% client-side WebRTC and MediaPipe worker execution.
- No regression in gesture recognition, ring buffer, or linguistics.
- Passing test suite (`npm test`) and Vite build (`npm run build`).
