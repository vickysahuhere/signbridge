  <files>src/workers/vision.worker.js</files>
  <read_first>tech.md, appflow.md</read_first>
  <action>
    Implement `src/workers/vision.worker.js`:
    - Import `@mediapipe/tasks-vision` (`FilesetResolver`, `HolisticLandmarker` or equivalent hand/pose/face multi-task landmarker).
    - Handle `INIT_VISION` message:
      - Resolve WASM binaries via CDN or local assets (`FilesetResolver.forVisionTasks`).
      - Check browser Cache Storage for model assets to enable instant subsequent loads.
      - Initialize landmarker with `runningMode: "VIDEO"` and `delegate: "GPU"`.
      - **Shader Warm-Up**: Run 1 dummy blank frame/tensor through the inference pipeline immediately upon initialization to trigger browser WebGL shader compilation.
      - Post message `{ type: "WORKER_READY", latencyMs }` to main thread.
    - Handle `PROCESS_FRAME` message:
      - Receive transferred `ImageBitmap` (or ImageData) and timestamp.
      - Execute `landmarker.detectForVideo(imageBitmap, timestamp)`.
      - Close `ImageBitmap` to avoid GPU memory leaks (`imageBitmap.close()`).
      - Post message `{ type: "LANDMARK_RESULTS", landmarks: { leftHand, rightHand, pose, face }, timestamp, processingTimeMs }`.
  </action>
  <verify>npm run build succeeds with worker module bundling; worker script contains warm-up call and HolisticLandmarker</verify>
  <acceptance_criteria>
    - src/workers/vision.worker.js handles INIT_VISION and PROCESS_FRAME
    - Implements WebGL shader warm-up before emitting WORKER_READY
    - Closes transferred ImageBitmap after detection
  </acceptance_criteria>
  <done>Worker thread ready to receive video frames and emit 543 3D landmarks</done>
</task>
